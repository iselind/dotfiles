`.task/` never reaches a pull request. It is consolidated, meaning promoted by the consolidate-docs skill and then deleted, before a pull request is created and before commits are pushed to a branch that has an open pull request. A pull request description never mentions `.task/` files.

**Why:** User said, after PR #1057 was opened with four `.task/` files in its diff: "the .task/ stuff should not find its way into a PR". `.task/` is scratch space and is committed on the branch during the work on purpose (see the knowledge-extraction plugin README). Pushing a branch with `.task/` on it is fine; what matters is that no pull request ever contains it, whether at creation or through a later push. The knowledge-extraction guard blocks PR creation and pushes to an open PR while `.task/` holds anything, but a command that chained a push and the PR creation once slipped past it, and the guard fails open when `jq`, `perl` or `gh` is missing.

**How to apply:** Pushing a branch that has no PR is fine with `.task/` still on it; the user said: "we can push a branch as long as there's no PR associated with it". Before creating a PR, or pushing to a branch that has one, run the consolidate-docs skill so `.task/` is promoted and deleted, and commit the deletion. Check `git diff origin/main...HEAD --stat -- .task` is empty. Create the PR only after that state is pushed, and run the push and the PR creation as separate commands. If `.task/` is already in an open PR, delete it in a normal commit; rewriting the branch history needs the user's approval. Do not write about `.task/` in a PR description (see [[pr_text_before_push]]).
