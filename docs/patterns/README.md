# Pattern Management

This directory stores documented, repeatable patterns for engineering tasks.

## Pattern Structure

Each pattern document should include:

- **Name** - Identifying label for the pattern
- **Intent** - What problem this solves
- **Applicability** - When to use this pattern
- **Constraints** - Limitations and preconditions
- **Process** - Step-by-step instructions
- **Verification** - How to confirm correct implementation
- **Limitations** - Known issues or edge cases
- **Maturity** - Experimental | Validated | Established

## Example Patterns

The following patterns have been identified as common needs:

- Add API endpoint
- Introduce background worker
- Modify Terraform configuration
- Investigate and resolve defects
- Introduce new technologies
