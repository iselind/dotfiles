**When to use:** During software engineering work involving:
- Code changes or refactoring
- Kubernetes/GitOps manifest work
- Terraform/IaC changes  
- Infrastructure-as-code patterns
- Domain-specific implementation tasks

**Why invoke:** Triggers the pattern-oriented LLM workflow that:
1. Understands objectives and constraints
2. Maps required domain knowledge to external sources
3. Analyzes gaps between current state and target
4. Decomposes into focused change pieces  
5. Discovers or establishes reusable patterns
6. Prepares execution steps with verification
7. Delegates to appropriate models/tools

**How it helps:** Externalizes methodology from model context, prevents knowledge bloat, surfaces relevant patterns dynamically rather than repeating the same reasoning patterns on every task.
